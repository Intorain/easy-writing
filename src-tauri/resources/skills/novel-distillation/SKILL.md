## 用途
把参考书变成一份能直接用来写作的文风档案。档案三层：
- 范例库：程序按模型标出的段落从原文取回的真实片段，按开章 / 对白 / 打斗 / 心理 / 过渡 / 收尾分类。写作时平台按场景类型把几段范例交给写作模型——写作模型学的是这些原文，不是形容词。
- 写法卡：不超过十来条可执行的做法，每条指向一段范例，经过一次对照原文的核验。只给规划与评审看，不给写作模型。
- 叙事模式：这本书怎么开篇、怎么换地图、怎么放信息，不含人名与专有设定，给规划模型用。
另有程序算的指纹（句长、段长、标点与比喻密度）只给作者看，不进任何提示词。
区分单作品文风与作者跨作品风格；只有一本书时说明这是该作品、该范围的风格。

## 整本书或指定章节的蒸馏
参考书的蒸馏使用持久任务，不用聊天里临时读几章代替。

- 用 list_breakdowns 核对当前引用的参考书，调用 prepare_distillation(project_id, focus)。工具会显示范围选择卡；作者选择全书或章节区间并确认后才调用模型。不要替作者选择范围，也不要根据已有拆书章数缩小范围。
- 后台按模型容量分片读取所选范围的全部原文：每片标出有辨识度的段落（不写观察、不抄原文）；归纳层对着这些段落的原文写写法卡与叙事模式；最后一次核验全部写法卡；范例库、指纹与技能文件由程序生成。调用次数约等于片段数加两三次。
- 进度卡区分原文阅读、归纳、核验和编档。已读取不等于已完成；状态由宿主返回，不从模型回复推测。
- 用 read_distillation 读取进度；通过 node_ref=job.rootNode 直达归纳结果，沿 children 读取下层节点。observations.evidence 中的编号可通过 evidence_ref 回查原文位置与版本。作者问进度时读取一次，不为等待完成反复轮询。
- 暂停、失败和应用退出保留已完成节点，可从卡片继续。原文版本改变时先说明旧分析已失效，不用旧结果冒充新版本的阅读。
- 同一作者多本书分别建立任务；不能把一本书的结论标成作者完整文风。

## 局部分析与更新
用户只询问某个片段、比较已有档案或修改技能时，先读 [分析方法](references/analysis.md)，使用 read_chapter、read_material 或 read_skill 读取实际材料，按其限定范围处理。作者自己的书可通过原有读取工具分析；需要后台逐章蒸馏时将该书的文本作为参考书导入。不能悄悄降级为开篇抽样后宣称完成整本书。

## 在平台上怎么做
- 后台任务完成后已有文风档案候选，不再重复 prepare_skill。候选先供编辑，作者点“保存技能”后才安装。
- 只有用户要求局部技能或修改已有技能时使用 prepare_skill；文风声明 kind=style，不填写 replaces。完整主写作方法才使用 kind=method 并明确替换目标。
- 手工写文风技能时，写法卡放 instructions（每条带范例编号），范例原文放 references/examples.json（examples 数组，每项 id / kind / text / source）；没有 examples.json 的文风技能写作时拿不到范例，只能靠前文续写。
- 候选可在成果面板修改；作者点击“保存技能”后才成为可调用技能。需要更新时先 read_skill 读取当前版本，再 prepare_skill 绑定 target_skill_id 与 target_revision；继续修改未保存候选则绑定 artifact_id 与 expected_revision。
- 作者保存后要试写或绑定作品，读取成果的 installedSkillId 或 list_skills 的真实编号，按仿书 Skill 应用。没有保存就不要编造技能编号或声称后续章节已经采用。
